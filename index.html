1️⃣ Aprendizaje por Refuerzo (Reinforcement Learning)

¿Qué es RL y cómo se diferencia del aprendizaje supervisado?

Aprendizaje por Refuerzo (RL): Es un paradigma donde un agente aprende a tomar decisiones interactuando con un entorno, recibiendo recompensas o castigos por sus acciones. El objetivo es maximizar la recompensa acumulada a lo largo del tiempo.

Aprendizaje Supervisado

  • Requiere datos etiquetados (X, y)
  • Aprende mapeos entrada → salida
  • La retroalimentación es inmediata
  • Datos fijos y predefinidos
  • Ejemplos: clasificación, regresión

Aprendizaje por Refuerzo

  • No requiere etiquetas explícitas
  • Aprende mediante prueba y error
  • Recompensas retrasadas y escasas
  • Genera sus propios datos interactuando
  • Ejemplos: juegos, robótica, control

Procesos de Decisión de Markov (MDPs)

Un MDP es una tupla formalizada que modela un problema de decisión secuencial:

MDP = (S, A, P, R, γ)
  • S: Conjunto de estados (todas las situaciones posibles)
  • A: Conjunto de acciones disponibles
  • P(s'|s,a): Probabilidad de transición (dinámica del entorno)
  • R(s,a,s'): Función de recompensa inmediata
  • γ ∈ [0,1]: Factor de descuento (importancia del futuro)
Propiedad de Markov: El futuro depende solo del estado presente, no de toda la historia. Esta es la propiedad fundamental que hace que los MDPs sean manejables computacionalmente.

Ecuaciones de Bellman

Las ecuaciones de Bellman son relaciones recursivas que descomponen el problema:

Función de valor de estado:

V(s) = Σ_a π(a|s) Σ_{s',r} P(s',r|s,a)[r + γV(s')]

Función de valor de acción (Q-function):

Q(s,a) = Σ_{s',r} P(s',r|s,a)[r + γ Σ_{a'} π(a'|s')Q(s',a')]

La ecuación de Bellman expresa que el valor de un estado es la recompensa esperada más el valor descontado del siguiente estado. Esto permite resolver el problema de forma iterativa.

Q-Learning (¿Por qué es Off-Policy?)

Q-Learning es un algoritmo que aprende la función Q-value óptima sin necesitar saber cuál es la política óptima durante el aprendizaje.

Actualización de Q-Learning:

Q(s,a) ← Q(s,a) + α[r + γ max_{a'} Q(s',a') - Q(s,a)]
¿Por qué es Off-Policy? Q-Learning es off-policy porque:
  • Usa una política de exploración (ε-greedy) para elegir acciones
  • Pero actualiza los Q-values basándose en el máximo Q-value futuro
  • No necesita que las acciones tomadas sean óptimas para aprender la política óptima
  • Esto permite balancear exploración vs explotación eficientemente

Problemas de Control vs Predicción

Aspecto Predicción Control
Objetivo Estimar V(s) bajo una política fija π Encontrar la política óptima π*
Política Dada y fija Debe ser mejorada iterativamente
Algoritmos Monte Carlo, TD(λ), etc. Q-Learning, Policy Gradient, Actor-Critic
Desafío Estimación precisa de valores Balance exploración/explotación

2️⃣ Clasificación Lineal - Perceptrón

Fundamentos del Perceptrón

El Perceptrón es el algoritmo más simple de aprendizaje supervisado para clasificación binaria lineal. Aprende un hiperplano que separa dos clases.

Función de predicción:

ŷ = sign(θ·x + θ₀)

Algoritmo del Perceptrón y Regla de Actualización

Pseudocódigo del Perceptrón:

  1. Inicializar θ = 0 y θ₀ = 0
  2. Para cada ejemplo (x_i, y_i) en el conjunto de entrenamiento:
  3. Si y_i(θ·x_i + θ₀) ≤ 0 (error):
    • θ ← θ + y_i x_i
    • θ₀ ← θ₀ + y_i
  4. Repetir hasta convergencia
Interpretación: Solo actualizamos cuando hay un error de clasificación. Movemos el hiperplano hacia el punto mal clasificado multiplicando por el signo de la clase (y_i ∈ {-1, +1}).

Teorema de Convergencia de Novikoff

Teorema de Novikoff: Si el conjunto de datos es linealmente separable, el Perceptrón convergerá en un número finito de iteraciones.

Cotas de convergencia:

Número de errores ≤ (R/γ)²

Donde:

  • R: Máxima norma de los datos ||x_i||
  • γ: Margen de separación mínimo
Limitación importante: Si los datos NO son linealmente separables, el Perceptrón nunca convergerá. Esta es la razón por la que SVM es superior (introdujo el margen suave).

Cálculo Manual: Ejemplo Resuelto

Problema: Determinar θ y θ₀ para los siguientes puntos:

Punto x₁ x₂ y
1 1 1 +1
2 2 2 +1
3 0 0 -1

Solución paso a paso:

Iteración 1: θ = [0, 0], θ₀ = 0

  • Punto 1 (1, 1, +1): 0·1 + 0·1 + 0 = 0 ≤ 0 → Error
  • θ ← [0,0] + 1·[1,1] = [1, 1]
  • θ₀ ← 0 + 1 = 1

Iteración 2: θ = [1, 1], θ₀ = 1

  • Punto 1 (1, 1, +1): 1·1 + 1·1 + 1 = 3 > 0 ✓
  • Punto 2 (2, 2, +1): 1·2 + 1·2 + 1 = 5 > 0 ✓
  • Punto 3 (0, 0, -1): -1·(0) - 1·(0) + (-1) = -1 ≤ 0 → Error
  • θ ← [1, 1] + (-1)·[0, 0] = [1, 1]
  • θ₀ ← 1 + (-1) = 0

Iteración 3: Todos los puntos clasificados correctamente

Resultado Final:

θ = [4, 4], θ₀ = -18

o θ = (4, 4), θ₀ = -18

Dependencia del Orden de los Puntos

Orden Importa: El Perceptrón es sensible al orden en que se presentan los ejemplos de entrenamiento. Diferentes órdenes pueden resultar en:
  • Diferentes pesos finales θ
  • Diferentes números de iteraciones hasta convergencia
  • Hiperplanos diferentes (todos válidos si los datos son linealmente separables)

Implicación: Para resultados reproducibles, es buena práctica usar un orden fijo o aleatorio con semilla (seed) controlada.

3️⃣ SVM - Máquinas de Vectores de Soporte

¿Por qué SVM es mejor que Perceptrón?

Mientras que el Perceptrón solo busca un hiperplano que separe los datos, SVM busca el hiperplano con el MÁXIMO MARGEN. Esto proporciona mejor generalización y manejo de datos no linealmente separables.

Formulación del Margen Máximo

Margen: Es la distancia más pequeña entre el hiperplano de decisión y los puntos de entrenamiento más cercanos.

Margen geométrico:

Margen = 2 / ||θ||

SVM resuelve el siguiente problema de optimización:

Problema primal (margen duro):

min 1/2 ||θ||²
s.t. y_i(θ·x_i + θ₀) ≥ 1 ∀i
Interpretación:
  • Minimizamos ||θ|| para maximizar el margen
  • Cada punto debe estar al menos a distancia 1 del hiperplano
  • Esto es un problema convexo con solución única

Vectores de Soporte

Vectores de Soporte: Son los puntos de entrenamiento más cercanos al hiperplano que determinan el margen. Cumplen la condición:

y_i(θ·x_i + θ₀) = 1

Características importantes:

  • Típicamente son el 10-30% de los datos
  • Los demás puntos pueden moverse sin cambiar la solución
  • La solución depende únicamente de los vectores de soporte
  • Esto hace SVM eficiente y robusto

Hinge Loss

Hinge Loss: Función de pérdida que permite violaciones suaves del margen (margen suave).

L(y, ŷ) = max(0, 1 - y·ŷ)
  • Si y·ŷ ≥ 1: Loss = 0 (clasificación correcta con margen)
  • Si y·ŷ < 1: Loss = 1 - y·ŷ > 0 (penaliza errores)
  • Permite puntos dentro del margen o mal clasificados

El problema de SVM con margen suave es:

Problema con regularización:

min 1/2 ||θ||² + C Σᵢ ξᵢ
s.t. y_i(θ·x_i + θ₀) ≥ 1 - ξᵢ
ξᵢ ≥ 0 ∀i
  • C: Hiperparámetro de regularización
  • ξᵢ: Variables de holgura (slack variables)
  • C grande: Penaliza errores más (margen duro)
  • C pequeño: Permite más errores (margen suave)

Dual de Lagrange y Condiciones KKT

El problema dual es más fácil de resolver numéricamente:

Problema Dual:

max Σᵢ αᵢ - 1/2 Σᵢⱼ αᵢαⱼyᵢyⱼ(xᵢ·xⱼ)
s.t. 0 ≤ αᵢ ≤ C ∀i
Σᵢ αᵢyᵢ = 0

Condiciones KKT (Karush-Kuhn-Tucker): Condiciones que caracterizan la solución óptima:

  1. αᵢ(y_i(θ·x_i + θ₀) - 1 + ξᵢ) = 0 (complementariedad)
  2. (C - αᵢ)ξᵢ = 0 (complementariedad 2)
  3. αᵢ ≥ 0, y_i(θ·x_i + θ₀) - 1 + ξᵢ ≥ 0

Implicación importante: Si αᵢ > 0, entonces x_i es vector de soporte (solo estos importan).

Propiedades Importantes de SVM

Propiedad Verdadero/Falso Explicación
SVM es convexo ✓ Verdadero Tiene un único mínimo global
SVM requiere datos normalizados ✓ Verdadero Por el parámetro C que controla el margen
Todos los datos son vectores de soporte ✗ Falso Típicamente solo 10-30% son vectores de soporte
SVM puede resolver problemas no lineales ✓ Verdadero Usando kernels (próxima sección)
C→∞ corresponde a margen duro ✓ Verdadero No permite violaciones del margen

4️⃣ Kernels y el Truco del Kernel

Mapeo a Espacios de Mayor Dimensión

El "truco del kernel" permite a SVM resolver problemas no lineales sin mapear explícitamente a espacios de altísima dimensión.

Idea Fundamental:

  1. Los datos no linealmente separables en bajo dimensión pueden serlo en alto dimensión
  2. Mapear datos: x → φ(x) (donde φ es muy costoso)
  3. El "truco": usar kernel K(x_i, x_j) = φ(x_i)·φ(x_j)
  4. Resultado: Obtenemos el beneficio del espacio alto sin computar φ explícitamente

Formulación dual con kernel:

max Σᵢ αᵢ - 1/2 Σᵢⱼ αᵢαⱼyᵢyⱼ K(xᵢ,xⱼ)

Tipos de Kernels

Kernel Polinomial

Kernel Polinomial de grado d:

K(x, x') = (x·x' + c)^d

Ejemplos comunes:

  • K1: K(x, x') = (x·x' + 1)² → mapeo cuadrático
  • K2: K(x, x') = (x·x' + 0)² = (x·x')² → productos internos cuadrados
  • K3: K(x, x') = (x·x' + 1)³ → mapeo cúbico

Interpretación: Mayor grado d = mayor complejidad del clasificador = más capacidad pero más riesgo de overfitting.

Kernel RBF (Gaussiano)

Kernel RBF (Radial Basis Function):

K(x, x') = exp(-γ ||x - x'||²)
o equivalentemente
K(x, x') = exp(-||x - x'||² / (2σ²))
  • γ o σ: Parámetro de ancho del kernel
  • γ pequeño (σ grande): Kernel suave, bajo margen (puede underfitting)
  • γ grande (σ pequeño): Kernel afilado, alto margen (puede overfitting)
  • Mapeo implícito: A espacio infinito-dimensional
  • Más flexible: Puede resolver casi cualquier problema no lineal

Margen Suave vs Margen Duro

Aspecto Margen Duro (C → ∞) Margen Suave (C finito)
Restricción y_i(θ·x_i + θ₀) ≥ 1 (exacta) y_i(θ·x_i + θ₀) ≥ 1 - ξᵢ (relajada)
Datos Debe ser linealmente separable Tolera datos ruidosos o outliers
Sesgo Alto (menos flexible) Bajo (más flexible)
Varianza Baja (generaliza bien) Puede ser alta si C es muy grande
Uso Datos perfectamente separables (raro) Datos reales (lo usual)

Identificación de Kernel por Gráfica

Claves para identificar kernels:

  • Límites lineales rectos: Kernel lineal (K = x·x')
  • Límites con curvas suaves: Kernel polinomial o RBF
  • Límites muy curvos/complejos: RBF con γ grande
  • Límites overfiteados (muchas curvas): Kernel muy complejo o C muy grande
  • Margen más estrecho: C más grande (penaliza más errores)
  • Margen más ancho: C más pequeño (tolera más errores)

Ejemplo Visual:

  • Si ves círculos o elipses como límites → Kernel polinomial bajo grado
  • Si ves límites muy irregulares → Kernel RBF o polinomial alto grado
  • Si ves líneas rectas → Kernel lineal (o SVM sin kernel)

5️⃣ Aprendizaje Profundo y Redes Neuronales

Maldición de la Dimensionalidad

Maldición de la Dimensionalidad: Fenómeno donde el volumen del espacio crece exponencialmente con la dimensión, haciendo que los datos se vuelvan dispersos.

Consecuencias:

  • Necesitamos exponencialmente más datos para mantener densidad
  • Las distancias entre puntos se vuelven menos significativas
  • Los datos caen principalmente en los bordes del espacio
  • Métodos como k-NN y clustering se vuelven inefectivos

Ejemplo numérico:

Dimensión 1: Rango [0,1], 10 puntos por unidad = 10 puntos
Dimensión 2: Cuadrado [0,1]², 10x10 cuadrícula = 100 puntos
Dimensión 10: Hipercubo, 10¹⁰ puntos necesarios!
Dimensión 100: 10¹⁰⁰ puntos (más que átomos en universo)
Solución: Deep Learning
  • Aprende representaciones de menor dimensión (embeddings)
  • Cada capa extrae características cada vez más abstractas
  • Reduce efectivamente la dimensionalidad del problema

Funciones de Regresión y MSE

Función de Regresión: Mapea entrada x a valor continuo ŷ.

ŷ = f(x; θ) = w_n^T σ(w_{n-1}^T σ(...σ(w_1^T x + b_1)...))

MSE (Mean Squared Error): Función de pérdida para regresión.

MSE = 1/m Σᵢ (yᵢ - ŷᵢ)²
  • Penaliza errores grandes más que errores pequeños (cuadrado)
  • Derivable, útil para descenso de gradiente
  • Sensible a outliers (por el cuadrado)

Deep Learning vs Shallow Learning

Aspecto Shallow (1-2 capas) Deep (3+ capas)
Capacidad Limitada a features lineales/simples Puede aprender features complejas y jerárquicas
Datos necesarios Menos datos (simple) Más datos (pero sigue siendo mejor con big data)
Tiempo de entrenamiento Rápido Puede ser lento (necesita GPUs)
Problemas resueltos Datos tabulares simples Imágenes, lenguaje natural, audio, etc.
Interpretabilidad Alta (puedes entender cada peso) Baja (cajas negras)

SGD - Descenso de Gradiente Estocástico

SGD: Variante de optimización que actualiza pesos usando mini-batches en lugar de todo el dataset.

Actualización SGD:

θ ← θ - α ∇L(θ; batch)

Comparación de métodos:

  • Batch Gradient Descent: Usa todo dataset → lento pero estable
  • Stochastic GD: Un punto → rápido pero ruidoso
  • Mini-batch SGD: Balance: rápido, estable y eficiente

Ventajas de SGD:

  • ✓ Escala a datasets enormes
  • ✓ Convergencia más rápida en práctica
  • ✓ Puede escapar mínimos locales (por ruido)
  • ✓ Usa menos memoria (no todo dataset en RAM)

Silver y Sutton - "Era de la Experiencia"

Concepto Clave (Silver & Sutton): Estamos en la "Era de la Experiencia" donde:

  • Datos > Algoritmos: La cantidad de datos es más importante que el algoritmo específico
  • Escala > Optimización: Redes grandes con datos masivos vencen optimizaciones ingenuas en pequeñas redes
  • Experiencia directa: Las redes aprenden mejor jugando/experimentando que desde datos etiquetados
  • Aprendizaje por refuerzo: Proporciona una fuente de "experiencia" infinita y automática

Implicación para Deep Learning:

  • ❌ No necesitas algoritmo "perfecto"
  • ❌ No necesitas features de ingeniería sofisticadas
  • ✓ Necesitas DATOS - cuantos más, mejor
  • ✓ Necesitas ESCALA - redes más grandes entrenadas más tiempo
  • ✓ Necesitas COMPUTACIÓN - GPUs/TPUs para escalar

Backpropagation

Backpropagation: Algoritmo para computar gradientes eficientemente en redes profundas usando regla de la cadena.

Regla de la cadena (esencia de backprop):

∂L/∂w = (∂L/∂ŷ) × (∂ŷ/∂h) × (∂h/∂w)

Algoritmo:

  1. Forward pass: Propagar datos desde entrada a salida, guardar activaciones
  2. Computar pérdida: L(ŷ, y)
  3. Backward pass: Propagar errores desde salida a entrada
  4. Actualizar pesos: θ ← θ - α ∇L

Complejidad:

Forward: O(n_parámetros)
Backward: ~2 × Forward

¿Por qué es eficiente?

  • Reutiliza computaciones (no recalcula derivadas)
  • O(n) no O(n²) donde n = # parámetros
  • Fundamental para entrenar redes profundas

Redes ReLU y Mapeo de Regiones

ReLU (Rectified Linear Unit): Función de activación más popular.

ReLU(x) = max(0, x)

Propiedades:

  • ✓ Computacionalmente eficiente
  • ✓ No satura (a diferencia de sigmoid/tanh)
  • ✓ Induce sparsidad (muchas unidades = 0)
  • ✓ Gradientes bien comportados
  • ✗ Neurona muerta: si ReLU(x) = 0 siempre, nunca aprende

Mapeo de Regiones con ReLU: Una red ReLU profunda mapea el espacio de entrada en regiones lineales por partes.

Cada región tiene su propio clasificador/regresor lineal. Con más capas:

  • 1 capa oculta: ~2 regiones
  • 2 capas ocultas: Potencialmente 2⁴ = 16 regiones
  • n capas ocultas: 2ⁿ regiones

Capacidad de aproximación:

Red profunda con d capas ≈ 2^(2^d) regiones

Implicación: La profundidad es exponencialmente más eficiente que el ancho para crear regiones complejas. Por eso "Deep" Learning.

Resumen: Por qué Deep Learning Funciona

  1. Jerárquía de características: Cada capa aprende features más abstractas
  2. Regularización implícita: ReLU + Dropout + Batch Norm evitan overfitting
  3. Eficiencia de representación: Profundidad exponencial en capacidad vs ancho
  4. Aprendizaje de escala: Más datos + más parámetros + más compute = mejor rendimiento
  5. Backprop eficiente: Entrenar redes de millones de parámetros es posible
